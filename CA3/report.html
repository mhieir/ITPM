3.1 پیش‌زمینه و خلاصه مدیریتی

روش محاسبه (CPM در یک نگاه)

گذر رو به جلو — Forward Pass:
ESj = max{ EFi } · EFj = ESj + Dj
گذر رو به عقب — Backward Pass:
LFi = min{ LSj } · LSi = LFi − Di
شناوری: TS = LS − ES = LF − EF · FS = min{ ESj } − EFi — فعالیت‌های با TS = 0 روی مسیر بحرانی قرار می‌گیرند.

3.2 شبکه PDM و جدول محاسبات

نمودار زیر شبکه فعالیت‌ها را به‌صورت Activity-on-Node نشان می‌دهد. هر گره شامل ES | EF در بالا، نام و مدت در میانه، و LS | LF در پایین است. مقادیر TS و FS نیز ذیل هر گره ثبت شده‌اند. مسیر بحرانی با رنگ قرمز پررنگ مشخص شده است.

3.3 وظیفه دوم — اعتبارسنجی با MS Project

در گام دوم، همان شبکه فعالیت‌ها در نرم‌افزار MS Project وارد شده و مقادیر Free Slack و Total Slack با استفاده از نمای Detail Gantt یا ستون‌های افزوده در Schedule Table استخراج گردیده است. تنظیمات کلیدی استفاده‌شده:

  1. Project Start Date = 2026-04-01 · Schedule from Project Start.
  2. تقویم ۲۴×۷ تعریف شد تا ماه‌ها منطبق با محاسبه دستی باشند.
  3. Task Mode = Auto Scheduled و وابستگی‌ها از نوع FS با Lag = 0.
  4. ستون‌های Free Slack و Total Slack از طریق Insert Column افزوده شد.

3.3.b تفسیر و مقایسه نتایج

مقادیر دستی و خروجی نرم‌افزار کاملاً منطبق هستند.

چرا اعداد یکسان شدند؟ هر دو روش از یک الگوریتم (Forward/Backward pass در CPM) استفاده می‌کنند. وقتی تمام روابط FS با Lag صفر، تقویم ۲۴×۷ و واحد ماه ≡ ۳۰ روز یکسان باشد، خروجی نرم‌افزار عیناً برابر محاسبه دستی است.
منابع اختلاف بالقوه (که اینجا رخ نداده‌اند): ۱) تقویم کاری متفاوت (تعطیلی جمعه‌ها) ۲) Schedule from Project Finish به‌جای Start ۳) ثبت Deadline در فعالیت پایانی که LF و در نتیجه TS را تغییر می‌دهد.

تحلیل شناوری در سطح فعالیت

  • UI/UX Design (#3) — TS = FS = ۲ ماه: پشت شاخه موازی غیربحرانی است. تیم طراحی می‌تواند تا ۲ ماه دیرتر آغاز کند بدون اثر بر تحویل. چون FS = TS، شناوری خصوصی است و مصرف آن، α Cross-Test را به تأخیر نمی‌اندازد.
  • Marketing (#8) — TS = FS = ۱ ماه: موازی Final Package. می‌توان تا ۱ ماه با تأخیر آغاز کرد. چون پس‌نیاز (#۹) با پایان همزمان #۷ و #۸ شروع می‌شود، شناوری آزاد و کل برابر است.
  • ۷ فعالیت بحرانی باقی‌مانده — TS = FS = 0: بافری ندارند. هر تأخیر مستقیماً تحویل را عقب می‌اندازد. Crashing buffer و بازبینی هفتگی پیشرفت توصیه می‌شود.
جمع‌بندی برای ذی‌نفع: پروژه با طول ۹ ماه در پنجره ۱۰ ماهه (Apr 2026 → Jan 2027) تحویل می‌شود؛ ۱ ماه بافر سطح-پروژه باقی است که باید پس از Final Package محافظت شود. تمرکز ریسک: شاخه توسعه (#۱) و فاز α/β Test.
